## 1. 目标与验收

### 1.1 目标

打通「打开小程序 → 切门店 → 看首页 → 看列表 → 看详情」这一条竖线，只服务 3 个真实商品。后台、登录、收藏、预约全部不在本阶段。

### 1.2 验收标准

| 项 | 标准 |
| --- | --- |
| 功能 | 小程序真机可看首页、上新、列表、详情；切换门店后库存与商品同步变化 |
| 数据 | 3 个真实商品、每款 2 色 × 3 尺码、三店库存有差异（一店售罄用于验证调货入口占位） |
| 性能 | 本机与公网测试环境接口 P95 < 300 ms（`/products` 列表 20 条） |
| 缓存 | 首页 / 详情 / 列表命中 Redis，写操作暂无（无后台写入口） |
| 回归 | 冷启动无迁移报错；`/actuator/health` UP；接口均有 `code/message/data` |

### 1.3 明确不做

登录与 JWT、收藏/点赞/足迹、试穿清单、预约、调货提交、后台全部接口、COS 上传、造型接口。

---

## 2. 关键设计决定（本阶段内定）

1. **库存不单独缓存**。M1 没有写入口，库存随商品查询直接读库；`xc:stock:*` 与失效逻辑留到 M1.5 引入后台写操作时再加。
2. **价格取 SKU 最小值**。列表页显示该商品在售 SKU 的最低 `price_cent`；`origin_price_cent` 同理取对应 SKU 的值。
3. **库存状态三档**：`OUT`（无在售 SKU 有货）、`LOW`（合计数量 ≤ 2）、`IN_STOCK`。`onlyStock=true` 只返回非 `OUT`。
4. **分页用游标前的简单页码**。`page/size`，`size` 上限 50，返回 `total` 与 `hasMore`；深翻不做优化。
5. **`/home` 一次返回整页**。主题 + 模块 + 每个模块的数据（商品卡片或造型卡片），避免小程序串行请求。
6. **用户态字段先固定假值**。详情返回 `favorited: false`、`liked: false`、`inCart: false`，M2 接登录后替换。
7. **包扫描调整**。两个启动类改为 `@SpringBootApplication(scanBasePackages = "com.xiachen.yishe")`，让 `xc-domain` 里的配置与领域服务被复用，而不是各应用复制一份。

## 3. 任务分解

### T1 通用层（xc-common）

| 文件 | 内容 |
| --- | --- |
| `xc-common/src/main/java/com/xiachen/yishe/common/web/ApiResponse.java` | `{code,message,data}`，`ok()` / `fail(code,msg)` |
| `.../common/exception/ErrorCode.java` | 40001 参数错误、40401 资源不存在、50000 系统错误 |
| `.../common/exception/BizException.java` | 携带 ErrorCode |
| `.../common/web/GlobalExceptionHandler.java` | `@RestControllerAdvice`，兜住校验异常与 BizException，未知异常打日志后返回 50000 |
| `.../common/cache/CacheTtl.java` | TTL 常量 + ±20% 抖动工具方法 |
| `.../common/web/PageResult.java` | `list/total/page/size/hasMore` |

验收：手动抛 BizException 时返回 `code` 非 0 且 HTTP 200。

### T2 领域层（xc-domain）

| 文件 | 内容 |
| --- | --- |
| `.../domain/entity/{Store,Product,ProductImage,Sku,Inventory,Look,LookItem,HomeTheme,HomeModule,Collection,CollectionProduct}.java` | 与 V1 表一一对应，用 `@TableName` / `@TableId` |
| `.../domain/mapper/*Mapper.java` | 继承 `BaseMapper`，复杂查询写 XML 或注解 |
| `.../domain/config/MybatisPlusConfig.java` | 分页插件 `PaginationInnerInterceptor(DbType.MYSQL)` |
| `.../domain/service/ProductQueryService.java` | 列表/详情的组装逻辑：SKU 聚合、价格取最小、三店库存、库存状态计算 |

不在 `xc-domain` 引入任何 Web 类型（Controller/DTO 放 xc-api）。

### T3 种子数据

| 文件 | 内容 |
| --- | --- |
| `V2__seed_store.sql` | 罗湖 / 福田 / 盐田三店：name、code、address、phone、营业时间、经纬度 |
| `V4__seed_demo.sql` | 3 个商品（含封面宽高）、每款 4 张图、2 色 × 3 尺码、三店库存（其中一店某 SKU 为 0）、1 个系列、1 个主题 + 4 个模块 |

`V3__seed_admin.sql` 不放在本阶段：管理员密码要 BCrypt 且不能明文入库，M1.5 用启动参数注入再落库。

注意：种子里的 `cover_url` 先用占位地址，真机联调前替换为 COS 实际地址；小程序后台需把 `img.xiachen.xyz` 加入 downloadFile 合法域名（开发者工具可临时关闭校验）。

### T4 接口（xc-api）

| 接口 | 主要逻辑 |
| --- | --- |
| `GET /api/v1/stores` | 查启用门店，按 `sort_no` |
| `GET /api/v1/stores/{id}` | 单店 + 营业时间 + 坐标 |
| `GET /api/v1/home?storeId=` | 取当前主题 → 模块 → 按类型装配：`BANNER` 返回图片，`COLLECTION/LOOK/RECOMMEND` 返回对应卡片列表（最多 10 条），`STORE` 返回门店胶囊 |
| `GET /api/v1/products` | 过滤：`storeId`（默认第一家在营门店）、`category`、`color`、`size`、`material`、`keyword`、`onlyStock`；排序：`recommend`（sort_weight desc）/`new`（online_at desc）/`priceAsc`/`priceDesc` |
| `GET /api/v1/products/{id}?storeId=` | 基本信息 + 图片（含宽高）+ SKU + 三店库存（含 `updatedAt`）+ 用户态假值 |

所有查询带 `status='ON'`；商品下线用 OFF，不物理删除。

响应示例（列表）：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [
      {
        "id": 1,
        "title": "醋酸缎面衬衫",

        "coverWidth": 760,
        "coverHeight": 1013,
        "priceCent": 69900,
        "originPriceCent": 89900,
        "likeCount": 12,
        "favCount": 5,
        "stockStatus": "LOW"
      }
    ],
    "page": 1,
    "size": 20,
    "total": 3,

  }

```

### T5 缓存

沿用 spec §8，只做三组：

| Key | TTL | 说明 |
| --- | --- | --- |
| `xc:home:{storeId}` | 10 min | 整页 `home` 响应体，序列化后存 |
| `xc:product:{id}` | 5 min | 详情响应体；`storeId` 影响库存，key 需带 `storeId` |
| `xc:list:{storeId}:{sha1(params)}` | 60 s | 列表响应体 |

空值缓存 60 s；TTL 加 ±20% 抖动。M1 无写入口，不做主动失效，靠 TTL 收敛。

## 4. 执行顺序

1. T1 通用层 → 编译通过
2. T2 实体 + Mapper + 分页插件 → 用 `mvn spring-boot:run` 验证启动
3. T3 V2 / V4 迁移 → 重启验证 Flyway 到 v4
4. T4 `/stores` → curl 验证（最简单，先跑通响应体与异常处理）
5. T4 `/products` → `/products/{id}` → `/home`（依赖前面的查询能力组装）
6. T5 缓存包装 → 用 redis-cli 验证 key 与 TTL
7. T6 小程序三页 + 两个组件
8. T7 单测与 MockMvc，补齐异常分支
9. 真机联调，替换真实图片地址

## 6. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 图片域名未配好，小程序真机白图 | 先用开发者工具关校验联调；COS 证书是并行任务，不阻塞代码 |
