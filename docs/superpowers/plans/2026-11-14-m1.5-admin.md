# M1.5 实施计划：后台登录与商品/库存维护

- 关联设计：`docs/superpowers/specs/2026-11-14-xiachen-yishe-design.md` §16 M1.5
- 前置状态：M1 浏览纵切可用（`/stores` `/home` `/products` `/products/{id}`），种子 10 款商品
- 周期：5 个工作日（单人）

---

## 1. 目标与验收

店长能在 H5 后台独立完成「登录 → 新建商品 → 上传图片 → 维护颜色尺码价格 → 改三店库存 → 上架」，前台小程序无需重启即可看到变化。

验收：不连数据库、不跑脚本，仅用浏览器录入 30 个真实 SKU；上下架与库存修改 10 秒内反映到 `/api/v1/products`。

## 2. 关键设计决定

1. **不引入 Spring Security 全家桶**，只用 `spring-security-crypto` 做 BCrypt，JWT 自行签发，过滤器保护 `/api/admin/**`。
2. **管理员不在迁移里写死密码**。启动时若 `staff` 为空，读取 `ADMIN_INIT_USERNAME` / `ADMIN_INIT_PASSWORD` 创建 ADMIN；未设置则跳过并打警告。
3. **图片先落本地磁盘**。`POST /api/admin/uploads` 返回 `url/width/height`；目录 `xc.upload.dir`（默认 `./uploads`），`/uploads/**` 静态映射。上 COS 时只替换存储实现。
4. **SKU 批量保存**。一次提交整组颜色×尺码；缺失的旧 SKU 置 `OFF` 而非物理删除，避免历史预约/调货断链。
5. **库存单条 upsert**。按 `(store_id, sku_id)` 写 `inventory`，`quantity=0` 即售罄；不做批量导入。
6. **写后即删缓存**。后台写商品/图片/SKU/库存后，删 `xc:product:{id}:*`、`xc:list:*`、`xc:home:*`；api 与 admin 必须共用同一个 Redis DB（统一 `REDIS_DB=2`）。
7. **审计留痕**。所有写接口落 `audit_log`（staff_id、action、target、detail），不做后台查看页，留到 M3。

## 3. 任务分解

### T1 认证与账号（xc-domain / xc-admin）

| 文件 | 内容 |
| --- | --- |
| `domain/entity/Staff.java`、`AuditLog.java` + Mapper | 对应 V1 表 |
| `admin/security/JwtService.java` | HMAC-SHA256，subject=staffId，claim role/storeId；secret < 32 字节直接启动失败 |
| `admin/security/AdminAuthFilter.java` | 解析 Bearer；`AdminContext` ThreadLocal 存当前账号；401 返回 `ApiResponse.fail(40101)` |
| `admin/bootstrap/AdminInitializer.java` | staff 为空时用环境变量建管理员，BCrypt 入库 |
| `admin/controller/AuthController.java` | `POST /api/admin/auth/login`、`GET /api/admin/auth/me`、`POST /api/admin/auth/logout`（前端清 token 即可） |

### T2 商品维护

| 接口 | 说明 |
| --- | --- |
| `GET /api/admin/products` | 关键词/状态筛选，返回 SKU 数、最低价、总库存 |
| `GET /api/admin/products/{id}` | 商品 + 图片 + SKU（含三店库存） |
| `POST /api/admin/products` | 新建草稿 |
| `PUT /api/admin/products/{id}` | 基本信息 |
| `POST /api/admin/products/{id}/publish` | `status=ON`，首次上架写 `online_at` |
| `POST /api/admin/products/{id}/offline` | `status=OFF` |
| `PUT /api/admin/products/{id}/skus` | 整组替换（按 color+size upsert，缺失置 OFF） |

### T3 图片直传

| 接口 | 说明 |
| --- | --- |
| `POST /api/admin/uploads` | multipart，jpg/png，≤ 8 MB；ImageIO 读宽高；返回 `{url,width,height}` |
| `POST /api/admin/products/{id}/images` | 绑定图片，`sortNo=0` 或首图时回写 `cover_url/width/height` |
| `DELETE /api/admin/products/{id}/images/{imageId}` | 解绑；删首图时顺延下一张为主图 |

### T4 库存维护

| 接口 | 说明 |
| --- | --- |
| `GET /api/admin/inventory?storeId=&keyword=` | 按门店列 SKU 与库存 |
| `PUT /api/admin/inventory` | `{storeId, skuId, quantity}` upsert |

### T5 前台缓存（M1 遗留）

`JsonCache` 封装 StringRedisTemplate + ObjectMapper；`/home` 10 min、详情 5 min、列表 60 s，TTL ±20% 抖动；Redis 不可用时降级直查。

### T6 后台前端（web）

| 页面 | 内容 |
| --- | --- |
| `/login` | 账号密码，token 存 localStorage，401 自动回登录 |
| `/products` | 表格：封面、标题、状态、价格、库存、操作（编辑/上下架） |
| `/products/:id` | 基本信息、图片上传、SKU 行编辑、保存/上架 |
| `/inventory` | 门店切换、搜索、行内改库存 |

### T7 验证

- `mvn package`、`npm run build` 通过
- curl 走一遍：登录 → 建商品 → 传图 → 存 SKU → 改库存 → 上架 → 前台 `/products` 可见
- 缓存：`redis-cli -n 2 keys 'xc:*'`；后台写后 key 消失

## 4. 不在本阶段

删除商品（只下架）、批量导入、COS 上传、角色权限细分、后台预约/调货看板（M3）。

## 5. 风险

| 风险 | 应对 |
| --- | --- |
| 后台与前台 Redis DB 不一致导致缓存不失效 | 统一 `REDIS_DB` 默认 2，写死在 compose/env |
| 本地上传目录随部署丢失 | 生产切 COS；compose 挂载 `./uploads` 卷 |
| 图片格式不支持 webp | 前端限制 jpg/png，后台二次校验 |
| JWT secret 为空 | `JwtService` 启动即抛错，避免无鉴权上线 |

## 6. 执行记录（2026-11-14 完成）

T1–T7 全部落地，与计划的差异：

1. **库存接口改为按商品返回矩阵**：`GET /api/admin/inventory?productId=` 返回 `{skus, stores, cells}`，一次给全三店；`PUT /api/admin/inventory` 提交 `{items:[{skuId,storeId,quantity,onSale}]}` 批量 upsert，比单条更适合后台表格保存。
2. **图片绑定接口补充**：`POST /api/admin/products/{id}/images/{imageId}/cover` 设主图；首图自动回写 `cover_url/width/height`，删主图时顺延下一张。
3. **上传 URL 前缀可配**：`xc.upload.public-base`（默认 `http://127.0.0.1:8082`），上 COS/域名后只改环境变量。
4. **实体 `updated_at` 加 `@TableField(updateStrategy = FieldStrategy.NEVER)`**：避免 `updateById` 把查询出的旧时间写回，交给 MySQL `ON UPDATE` 维护。
5. **后台前端**：`/inventory` 以「选择商品 → SKU×门店矩阵」为主，不再按门店切页；商品列表/编辑页含图片上传、SKU 行编辑、上下架、库存入口。
6. **验证**：`mvn package`、`npm run build` 通过；curl 与浏览器双路径走完 登录 → 建品 → 传图 → SKU → 库存 → 发布 → 前台可见，后台写入后 `xc:*` 缓存 key 全部失效，`audit_log` 记录 6 类动作；校验了未登录 401、发布缺图/缺 SKU 报错、下线后前台 40401。
7. 本地账号：`admin / xiachen_dev`（仅存在于被 `.gitignore` 忽略的 `application-local.yml`，首次启动建号；生产用 `ADMIN_INIT_*` 环境变量）。
8. **追加「首页配置」**（原计划留到 M4）：`GET/PUT /api/admin/home` + 前端 `/home-config`，可改首屏大图（同步 `home_module.BANNER.image_url` 与 `home_theme.cover_url`）、主题名与文案、造型封面、门店封面；保存后失效 `xc:home:*`。M4 只再补「多主题切换与模块排序」，店主不再需要碰 SQL。
