## 1. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/auth/wx-login` | 请求头 `X-App-Id` + body `{code, nickname?, avatarUrl?}`；返回 `token / expiresIn / user` |
| GET | `/api/v1/auth/me` | 需要 Bearer；返回当前用户 |
| PUT | `/api/v1/auth/profile` | 需要 Bearer；改 `nickname` / `avatarUrl` |
| POST | `/api/v1/auth/logout` | 无状态，客户端清本地会话即可 |
| GET | `/api/v1/favorites`、`/likes` | 需要 Bearer；`targetType=1` 商品、`2` 造型，分页 `page/pageSize` |
| POST | `/api/v1/favorites`、`/likes` | 需要 Bearer；body `{targetType, targetId}`，幂等 |
| DELETE | `/api/v1/favorites`、`/likes` | 需要 Bearer；查询参数 `targetType&targetId` |

`GET /products/{id}` 在携带合法 token 时叠加 `favorited / liked`；匿名访问仍是 false。

## 2. 关键决定

- **缓存不掺用户态**：`xc:product:*` 只缓存匿名详情，登录态在返回前叠加，避免不同用户互相污染。收藏/点赞写成功后按前缀失效 `xc:product:` `xc:list:` `xc:home:`（列表与首页卡片含计数），本轮用户量下可接受。
- **JWT 与后台隔离**：同一个 `jwt.secret`，用户 token 带 `scope=user`，后台 token 无此 claim；解析时校验 scope，TTL 7 天（`jwt.ttl-days`）。
- **多 AppID**：`X-App-Id` 选择配置：`wechat.apps` 按 appid 匹配，`app_user` 以 (appid, openid) 唯一。未注册的 AppID 直接失败，不落库。
- **本地 mock**：`wechat.mock=true`（`WX_MOCK`，本地 `application-local.yml` 已开）时按 `mock_<appid>` 生成固定 openid，开发者工具用 `touristappid` 可完整走通；配置和代码都不向真实 AppID 数据写入。
- **昵称/头像**：微信不再静默返回，登录接口可带用户主动填写的值；小程序先用 `wx.showModal` 可编辑弹窗改称呼，头像上传留到后续（`avatarUrl` 字段已预留）。
- **计数**：`INSERT IGNORE` + 唯一键保证重复收藏/点赞不重复加数；取消仅在实际删除行后 `GREATEST(count-1,0)`，避免负数。

## 3. 代码落点

- 实体/映射：`xc-domain` 新增 `AppUser`、`AppUserMapper`、`UserMarkMapper`（收藏与点赞共用一套多态 SQL，表名与计数列只来自服务端枚举）。
- 鉴权：`xc-api/security` 新增 `UserJwtService`、`UserContext`、`UserAuthFilter`；过滤器只处理 `/api/v1/**`，无 token 放行、坏 token 返回 HTTP 401 + `40101`。
- 登录：`WechatClient`（RestClient，3s/5s 超时，jscode2session 失败统一 `40104`）、`AppUserService`、`UserAuthController`。
- 收藏点赞：`UserMarkService` + `UserMarkController`，目标必须是 ON 状态的商品/造型。
- 小程序：`utils/auth.js`（登录、会话持久化、401 自动重登并重试一次）、`utils/request.js`（401 清会话、登录失效不弹 toast）、商品详情（爱心点赞、底部收藏）、我的（登录态、改称呼、收藏/点赞列表、分页、退出）。

## 6. 第二批接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/footprints?limit=50` | 需要 Bearer；默认 50，最多 100；按 `viewed_at` 倒序，顺带清理 30 天前 |
| DELETE | `/api/v1/footprints` | 需要 Bearer；清空本人足迹 |
| GET | `/api/v1/tryon-items` | 需要 Bearer；按门店分组（门店 `sort_no` 升序），每项带本店库存状态 |
| POST | `/api/v1/tryon-items` | 需要 Bearer；body `{skuId, storeId}`；`(user, sku, store)` 幂等 |
| PATCH | `/api/v1/tryon-items/{id}` | 需要 Bearer；body `{storeId}`；换店时若目标已有同 SKU 则合并删除 |
| DELETE | `/api/v1/tryon-items/{id}` | 需要 Bearer；只能删自己的 |
| POST | `/api/v1/appointments` | 需要 Bearer；body `{storeId, visitDate, visitTime?, phone, contactName?, remark?, clientRequestId, skuIds[]}` |
| GET | `/api/v1/appointments?page&pageSize` | 需要 Bearer；倒序分页，`pageSize` 上限 50 |
| GET | `/api/v1/appointments/{id}` | 需要 Bearer；含商品明细与门店信息 |
| PATCH | `/api/v1/appointments/{id}` | 需要 Bearer；取消（幂等，已到店不可取消） |

`GET /products/{id}` 登录态额外返回 `inCart`；每个 SKU 增加 `storeStocks[{storeId, quantity}]`（三店），供详情页展示与选店。足迹在登录态成功读取详情后写入。

## 7. 第二批关键决定

- **足迹**：唯一键 `(user_id, product_id, store_id)`，`INSERT ... ON DUPLICATE KEY UPDATE viewed_at`；不对 `store_id=0` 特判，匿名 / 未选店也按 0 记一行。只保留 30 天，读取时先删过期行，不额外起定时任务。
- **试穿清单**：按 SKU 维度而非商品维度；加入时要求 SKU、商品、门店均 ON，门店不可选时报“门店暂不可选，请换一家”。换店用一次 `UPDATE`，撞唯一键说明目标店已有同 SKU，删除旧行完成合并。清单页过滤已下架 SKU / 商品 / 门店。
- **预约**：**不扣库存、不限人数**。时间固定 30 分钟一档（10:00–20:30）+「时间待定」，必须在门店营业时段内、不能早于今天、最多 30 天后；`client_request_id` 唯一键做客户端幂等，先查后插并捕获唯一键冲突返回已有预约。取消只允许 `PENDING / CONFIRMED`，`DONE` 拒绝；重复取消直接返回当前状态。`item_count` 写入时快照，`appointment_item` 记 SKU 且应用层去重。
- **SQL 落点**：足迹 / 清单的 upsert 与按门店计数、换店、删除全部写在 Mapper 注解 SQL 里，避免 XML；分页统一 `selectPage` 后补商品/门店名称。
- **用户态隔离**：详情缓存仍只存匿名视图，`inCart` 与足迹写入在缓存读取之后叠加，未登录不写足迹。

## 8. 第二批代码落点

- 实体 / Mapper：`xc-domain` 新增 `UserFootprint`、`TryonItem`、`Appointment`、`AppointmentItem` 及对应 Mapper（`TransferOrder` 已于 M3 删除）；`UserFootprintMapper`、`TryonItemMapper` 带注解 SQL（upsert / recent / deleteBefore / countProduct / moveOwned）。
- 服务：`FootprintService`（30 天保留、按店库存聚合）、`TryonService`（加/移/删/按店分组）、`AppointmentService`（时间与 SKU 校验、幂等、取消）。
- 接口：`FootprintController`、`TryonController`、`AppointmentController`；`ProductController` 详情叠加 `inCart` 并记录足迹。
- 详情视图：`ProductDetailView.SkuView` 增加 `storeStocks`，`CatalogService.product()` 复用在线门店列表一次性拼三店库存。
- 小程序：`utils/format.js`（日期/时间/门店短名/请求 ID）；清单页重写（勾选、按店预约弹层、日期/时间/手机号、提交后跳「我的预约」）；新增足迹页（按天分组、清空）、我的预约页（状态、明细、取消）；商品详情底部为「加入试穿清单 / 预约到店」；「我的」页新增足迹/预约入口。
