# M3 后台实施记录（预约看板 + 造型维护）

日期：2026-11-14
范围：后台预约看板、造型维护；跨店调货下线。小程序侧本轮只做删减（移除调货入口与「我的调货」页）。

## 1. 接口

### 1.1 预约看板 `/api/admin/appointments`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/appointments?date&status&storeId&page&pageSize` | `date` 默认今天；按到店时间升序；`pageSize` 默认 50、上限 100 |
| GET | `/api/admin/appointments/{id}` | 明细：门店地址/电话 + 预约商品（SKU、颜色尺码、标题、封面、价格） |
| PATCH | `/api/admin/appointments/{id}` | body `{status}`，只接受 `CONFIRMED / DONE / CANCELED` |
| GET | `/api/admin/stores` | 门店下拉（`id / name / address`，仅 ON，按 `sort_no`） |

### 1.2 造型维护 `/api/admin/looks`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/looks?keyword&status&page&pageSize` | 标题/描述模糊搜索，按 `sort_no, id` 升序，带单品数量 |
| GET | `/api/admin/looks/{id}` | 明细：封面、文案、状态、单品（按 `sort_no`，附最低在售价） |
| POST | `/api/admin/looks` | 新建，落 `DRAFT` |
| PUT | `/api/admin/looks/{id}` | 改标题/描述/封面/排序 |
| PUT | `/api/admin/looks/{id}/items` | body `{productIds[]}`，全量覆盖；顺序即展示顺序，去重，最多 12 件 |
| POST | `/api/admin/looks/{id}/publish` | 需封面 + 至少一件单品，置 `ON` |
| POST | `/api/admin/looks/{id}/offline` | 置 `OFF` |

## 2. 关键决定

- **状态机**：允许目标仅 `CONFIRMED / DONE / CANCELED`；`PENDING→CONFIRMED`、`CONFIRMED→DONE`、`PENDING|CONFIRMED→CANCELED`。同状态重复提交视为成功（幂等），非法流转返回 40001「当前状态「x」不能改为「y」」。
- **并发**：更新用 `UPDATE ... WHERE id=? AND status=?` 条件更新，先读后写只用于文案；两人同时点「确认」不会把已取消单改回来。
- **门店隔离**：`MANAGER` 强制本店——列表传别店 `storeId` 返回 `FORBIDDEN`；明细/更新访问别店预约按 `NOT_FOUND` 处理，不泄露存在性。`ADMIN` 可跨店，`storeId` 为空表示全部门店。
- **造型单品顺序**：全量覆盖 + `sortNo` 按提交数组下标写入；`LinkedHashSet` 去重；校验 `productIds` 必须全部存在（`selectBatchIds` 数量比对），否则 40401「部分商品不存在，请刷新后重试」。
- **发布校验**：封面为空 →「发布前请先上传造型封面」；零单品 →「发布前请至少添加一件单品」。草稿可随意保存不校验。
- **缓存**：预约不改目录数据，不 evict；造型任何写操作（含单品）都 `evictCatalog()`，保证首页 `/home` 的 LOOK 模块及时更新。
- **审计**：预约改状态记 `APPOINTMENT_STATUS`（`from/to`）；造型记 `LOOK_CREATE / LOOK_UPDATE / LOOK_ITEMS / LOOK_PUBLISH / LOOK_OFFLINE`。审计日志不因测试清理物理删除。
- **调货删除方式**：迁移只删表，不保留历史；这是功能下线而非审计数据，历史迁移文件（V1/V4/V5 提到 `transfer_order`）保持不动，Flyway 校验和不变。
