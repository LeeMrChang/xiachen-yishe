# M4 实施记录：首页主题编排、监控告警、提审材料

范围：多主题编排与时间窗切换、模块增删排序、门店资料/封面维护与新增/上下线、健康检查与告警、小程序提审材料。验收目标「运营可自主换主题」已满足。

## 1. 后台接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/home-themes` | 主题列表：名称、封面、时间窗、状态、是否当前、模块数、更新时间 |
| GET | `/api/admin/home-themes/{id}` | 主题详情，含模块（类型中文名、引用对象名） |
| POST | `/api/admin/home-themes` | 新建主题，默认 `DRAFT`、非当前 |
| PUT | `/api/admin/home-themes/{id}` | 改名称/文案/封面/时间窗/状态 |
| PUT | `/api/admin/home-themes/{id}/modules` | 全量保存模块，数组顺序即首页展示顺序 |
| POST | `/api/admin/home-themes/{id}/activate` | 设为当前主题 |
| POST | `/api/admin/home-themes/{id}/offline` | 下线并取消当前标记 |
| GET | `/api/admin/collections` | 系列下拉（不含 OFF） |
| GET | `/api/admin/stores` | 营业中门店下拉 |
| GET | `/api/admin/stores/covers` | 门店完整信息（含营业时间、封面、状态） |
| POST | `/api/admin/stores` | 新增门店（仅 ADMIN），编码唯一、默认 `ON`、排序排最后 |
| PUT | `/api/admin/stores/{id}` | 更新门店名、地址、电话、营业时间 |
| PUT | `/api/admin/stores/{id}/status` | 上线 / 下线门店（仅 ADMIN，`ON` / `OFF`） |
| PUT | `/api/admin/stores/{id}/cover` | 更新门店封面 |

原 M1.5 的 `GET/PUT /api/admin/home` 与前端「首页配置」页在 M4 合并后下线。

## 2. 关键决定

- **选主题**：`CatalogService.home` 取 `status=ON` 且当前时间落在 `[start_at, end_at]`（空值不限）的主题，按 `is_current`、`start_at`、`id` 倒序取第一条。运营手动「设为当前」优先级最高；时间窗到期后自然回落到下一套。
- **启用门槛**：设当前要求主题 `status=ON`，且已启用 BANNER 并有首屏图（BANNER 图或主题封面），避免首页出现无图首屏。
- **模块规则**：BANNER / RECOMMEND / STORE / LOOK 各最多一个；COLLECTION 最多 3 个且同一系列只能出现一次；系列、门店引用必须存在。`ref_id` 只对 COLLECTION / STORE 保留。
- **下线即取消当前**：`offline` 同时置 `is_current=0`，不自动指定继任主题；首页仍会按时间窗回落到其它 ON 主题。
- **表单不覆盖全局数据**：模块只保存主题自己的图片；造型封面走「造型维护」，门店信息与封面走「门店」页，避免两处入口互相覆盖。
- **门店资料可维护**：名称、地址、电话、营业时间在「门店」页直接编辑；营业时间要么两端都填、要么都留空（不限时段），开始必须早于结束；MANAGER 只能改本店（其它门店按 40301 拒绝）。
- **门店新增与下线**：仅 ADMIN 可新增（编码唯一、2–32 位字母/数字/下划线/短横线、转大写）与上下线（`PUT /{id}/status`）；不物理删除，下线用 `OFF`。下线后 C 端门店列表/详情、首页 `STORE` 模块、预约与试穿选店均不再出现该店；后台门店页保留为灰色卡片，可重新上线。新门店默认 `ON`，`sort_no` 取当前最大值 +1。
- **入口合并**：删除「首页配置」页面、路由、导航与后端 `/api/admin/home`，导航改为「首页主题」「门店」。原页面独有的造型/门店封面编辑分别落到「造型维护」与新「门店」页。
- **监控取轻量方案**：单机 3.6 GB 内存，不引入 Prometheus/Grafana；cron + curl 健康检查 + 企业微信机器人，容器日志限制大小。
- **提审材料**：隐私指引、审核说明与截图清单单独成文（`docs/release/miniprogram-submission.md`），上线前按清单逐项核对。

## 5. 遗留

- 主题暂不支持删除（下线保留即可，避免误删运营素材）。
- 造型/系列仍无独立后台 CRUD；系列通过种子或 SQL 维护。
- 门店不提供物理删除，下线用 `ON/OFF` 状态；编码创建后不可修改，排序保持只读。
- 定时备份、cron 安装、企业微信 webhook 与真实域名/证书均属服务器侧动作，需上线时在 `/etc/environment` 或 cron 中配置 `ALERT_WEBHOOK_URL`。
- 小程序订阅消息（预约提醒）未接；提审材料中已按现状说明。
- 本地 IDEA 运行的 xc-api（8081）/ xc-admin（8082）需重启后才能加载新接口与选主题逻辑。
